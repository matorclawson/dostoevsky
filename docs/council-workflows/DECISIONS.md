# Review notes for the activity lifecycle

Review the activity lifecycle commit on top of the external candidate (`1745c8a2`) and the cache and fresh-publishing commits (`93acac3`, `78dc8f4`). The design documents are kept alongside these notes.

1. **Status.** This is an experimental embedded package. Verify the ten process-kill cases and the public reference suite before integrating. Do not retire Ephemeral or switch users.
2. **Torn groups first.** Track a durable committed byte boundary tied to a store generation, segment ID, offset and checksum. Recovery must verify acknowledged data through that point and limit tail repair to higher offsets. Publish a new boundary crash-safely across rollover and sync it before replying. A straightforward separate witness adds a durability barrier per group. Measure that implementation before optimizing the barrier. A marker appended to the same unsynced write alone cannot establish which client replies escaped. Test a corrupt final group, a corrupt earlier committed group, witness damage, rollover, and a lost reply. Retain fail-closed behavior meanwhile.
3. **Replication.** Build a deterministic three-voter replicated-log simulator before a distributed server. Use monotonically increasing terms, durable votes and log entries, leader matching and majority commitment for current-term entries. Expose a committed index to readers and release replies only for committed transitions. Validate conflicts in log order. Fence stale leaders for lease operations, use committed lease grants, and define clock-skew bounds for expiry on leader changes. Persist membership, use joint consensus for changes, and install verified snapshots before compacting prefixes. Exercise partitions, lost ACKs, stale leaders, diverged tails, snapshot interruption and machine loss. Record minority unavailability. Require a three-machine restore and failover test before any replicated claim. Keep single-copy sync benchmarks separate.
4. **Workflows as code.** Declarative graphs fit activities, waits and joins. Ship the conformance and state-storage foundation first. A deterministic Go SDK would also require a versioned command history, replay compatibility tests, recorded nondeterminism, and a code-upgrade policy for runs already in flight. Prototype those against real workflows whose logic is awkward as a graph. Temporal SDK interoperability is a larger independent commitment covering wire service semantics, workflow task dispatch, history pagination, SDK replay fixtures, cancellation and version compatibility. Treat it as a separately funded compatibility project. The current package measures activity orchestration only.
5. **Batched streaming.** Benchmark a matrix of explicit batch bytes, linger and producer count. Include consumer-visible p99, backlog drain and allocations at identical durability. Profile frame copies and syncs per group before changing the on-disk representation. Correlate each acknowledged batch with readback following restart. Separate explicit batch atomicity from group sync of independent records; today's public PublishBatch allows a recoverable prefix.
6. **Kafka wire.** Preserve the native protocol for the first performance baseline. Before committing to Kafka compatibility, test demand using an opt-in adapter covering API negotiation, metadata, produce and fetch with two stock clients. Offset commits, group rebalancing and transactions need separate conformance milestones. Measure the full adapter process footprint and failure semantics.
7. **Pass rules.** Keep the non-overlap rule, publish paired trial values and exclusions, and name each workload won or lost. Report offered versus completed work, client saturation, backlog, crash-oracle violations and matched durability. Compare equal workflow outcomes, and include Temporal's database and worker resource costs under stated boundaries. An unmatched durability profile is a separate table. Do not infer leadership from these embedded measurements.
8. **Next milestones.** Require bounded resident history, snapshot recovery and a deadline index tested against a million live timers independently of a million closed runs. Then measure disabled, idle and busy co-location. Validate the trigger's store-generation and immutable-settings binding and its start-before-cursor crash cases before enabling it. Separate network request receipts from exact-once external effects.
