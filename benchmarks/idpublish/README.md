# Publishing with retained IDs

For the embedded test, choose an ext4 test volume and run `GOMAXPROCS=2 make dev-id-publish RECOVERY_PARENT=/path/to/volume ID_HISTORY=10000000`. Also use `ID_HISTORY=1000000` for the smaller case. Runs create a new fixture, write deterministic 32-character IDs and eight-byte values, migrate a copy, and publish through the public Go API in each format. Each cell starts a fresh process. It checks receipt offsets, distinguishes fresh IDs from exact retries of the first and last seeded records, and reports latency, process RSS, exact probes and cold index loads. The rollover case uses 512-byte values and reports latency for the first measured receipt in each new segment. Migration performed with a current binary creates the filter hints as it seals segments.

For the wire comparison, install the dependencies from `benchmarks/clients/python/requirements.txt` and the JavaScript lockfile in `benchmarks/clients/javascript`. Build `./cmd/serve` from the separate `benchmarks/embedded` Go module. Set `SERVE_BIN`, `BENCH_NATS_SERVER`, `BENCH_KAFKA_HOME`, `BENCH_JAVA_HOME` and `JAVA_HOME` to the appropriate absolute paths. Use `TMPDIR` on the test volume. Run `make dev-id-peers ID_PYTHON=/path/to/venv/bin/python` and `make dev-id-eventloop`. The production Go library has no dependencies on these benchmark clients or brokers.

The Python trials give each of 1 or 32 workers one outstanding single-record request. Dostoevsky uses a pool of native socket clients, NATS uses its Python client on an asyncio loop bridged to the workers, and Kafka uses librdkafka with an idempotent producer, one message per batch and all acknowledgements. Each broker uses one local copy and durable sync settings. Kafka receives the application ID as the message key. Its idempotent producer tracks retries through its producer session. JetStream handles message IDs within its configured duplicate window. Dostoevsky retains IDs as long as their records remain. Each engine starts with an empty store. The verification client survives a broker SIGKILL and reads each recorded offset after restart. The JavaScript cross-check removes the Python thread-to-asyncio bridge and verifies every timed offset before shutdown.
